NetCoreClient：TOC + XML + Lua 界面加载

基于 Ghidra 对 WoW.exe 1.12.1（zhCN）的分析补全的界面加载功能，以及测试结果。

结论：NetCoreClient 现在能按 WoW.exe 的方式加载 TOC + XML + Lua 界面。新增的 --glue 模式可以显示真实的登录界面：加载真实 GlueXML（37 个文件、770 个框体）时 0 个 Lua 错误，整个解决方案编译通过，54 个测试全部通过（含原有的 32 个）。

效果截图

运行方式

dotnet run --project src/Client -- --glue [--accept-eula] [--no-loose] [--data <Data 目录>]
  • --accept-eula：视为已接受 EULA 和使用条款，直接进入登录屏。
  • --no-loose：只读 MPQ，不叠加游戏目录下的散文件（与正版行为一致）。
  • --frames N --screenshot file.bmp：渲染 N 帧后截图退出。
  • 加载日志写在临时目录的 NetCoreClient-GlueXML.log。

从 Ghidra 分析出的加载流程

启动顺序

阶段函数步骤
Glue（登录界面）FUN_0046a7b0 初始化 Lua（FUN_00703b80，内含 compat.lua）→ 注册 Glue API（FUN_0046abb0）→ 注册 26 个 Glue 事件（FUN_0046cc60）→ 签名校验（GlueXML.toc.sig，276 字节）→ 加载 TOC → 触发 FRAMES_LOADED → 切到 "login" 屏幕（SET_GLUE_SCREEN）

TOC 解析（FUN_006edb90）

  • 跳过 UTF-8 BOM，按行拆分。
  • # 开头的行不算文件；## Key: Value 是元数据（Interface、Title、Notes、Dependencies 等，见 FUN_0051c9b0）。
  • 文件名去掉尾部空格，以 TOC 所在目录为相对路径。

单个文件（FUN_006ede10）

  • .lua 文件直接执行，失败时记录 “Error loading %s”。
  • XML 顶层元素分四类：
    • Include file=：始终相对当前文件所在目录。
    • Script file=：路径中不含 \ 时才按相对路径处理；内联脚本的 chunk 名为 文件名:<Scripts>。
    • Font：进入字体表，必须有名字。
    • 其余：带 virtual="true" 的注册为模板，重名时先注册的生效（“Virtual object named %s already exists”）；否则创建框体。

创建框体（FUN_006ee280 → FUN_00769820 → FUN_0076a2f0）

  1. 按标签名找框体类型，找不到时记录 “Unknown frame type: %s”。父框体取自 parent 属性或模板的 parent。
  2. 先套用 inherits 模板（递归 LoadXML）。
  3. 处理 Size/Anchors（FUN_00767800，支持 $parent）、各属性、Backdrop、HitRectInsets、Layers 和 Scripts。每个脚本单独编译为名为 “框体名:脚本名” 的 chunk。
  4. 创建 <Frames> 子框体（模板中的子框体在前）。子框体先运行 OnLoad，父框体后运行；父框体可见且尚未触发过 OnShow 时，再补一次 OnShow。
  5. 脚本运行时把全局 this 设为当前框体，运行完恢复原值（FUN_00704d50）。

区域（Texture / FontString）

  • XML 中没有锚点的区域自动填满父框体（FUN_007701c0）。
  • 贴图缺失时整块填绿色，并记录 “Texture %s: Unable to load texture file %s”。
  • FontString 的 inherits 先查字体对象、再查模板；text 属性优先查同名全局字符串（FUN_00703bf0）。

警告文案与客户端日志原文一致，例如 “Couldn't find inherited node”、“Couldn't find relative frame”、“Unknown frame type”。

Lua 5.0 兼容

引擎使用 MoonSharp（Lua 5.2）。加载前做一层词法转换，并补上 compat.lua 里的全局函数：

  • for k,v in 表 do 自动包装成迭代器。
  • 变参函数补上隐式 arg 表（含 arg.n）。
  • 把作为普通标识符使用的 goto 改名。
  • 5.0 能接受的 \%、\[ 等转义去掉反斜杠。
  • 全局函数：getn、tinsert、mod、strupper、角度制 sin/cos、getglobal 等。

转换不增加换行，报错行号与原文件一致。

客户端渲染

  • src/Client/GlueGame.cs：--glue 模式，负责加载界面，并把鼠标、滚轮和键盘事件转发给 UI。
  • src/Client/Ui/GlueRenderer.cs：通过 ImGui 绘制 Backdrop（平铺背景加八段边框）、贴图（含纹理坐标和 ADD 混合近似）、文字（颜色码、阴影、描边、自动换行）、编辑框光标，以及滚动区域裁剪。字体使用 MPQ 中的方正字体，字形集合由界面实际用到的字符生成。

需要注意的几点

  • 游戏内 FrameXML 还剩 281 个 Lua 错误。都是缺少 UnitName、GetItemQualityColor 这类依赖游戏状态的 C 函数，界面结构本身完整。需要等网络和世界状态接入后再补。
  • 散文件优先是有意为之。正版 exe 启动时会把散放的 Interface\GlueXML 改名为 .old（FUN_0051fb50），签名校验（FUN_006f10f0）也会拒绝修改过的 GlueXML。这里保留散文件优先、跳过签名校验，ServerAddress.xml 才能生效。要与正版完全一致，请使用 --no-loose。
  • 尚未实现：
    • 登录背景的 3D 模型（ModelFFX）不渲染，背景为黑色。
    • 登录按钮目前只弹出“正在连接”，还没有真正联网。
    • 滚动条滑块不能拖动；滚轮和上下按钮可用。
  • 两处是推断，而非直接从反编译读出：
    • 显示框体时先显示子框体、再运行父框体的 OnShow。依据：只有这个顺序才能让 AccountLogin_OnShow 最终把焦点交给账号框。
    • SimpleHTML 的 file 属性要补 Data\ 前缀，因为 MPQ 中实际存的是 Data\eula.html。
  • 中文客户端里看不到“记住帐号名”复选框是正常的：GlueLocalization.lua 在 zhCN 下会将其隐藏。
  • scan.html、contest.html、survey.html 在这份客户端的 MPQ 中不存在，日志里对应的 3 条警告反映的是真实数据情况。
